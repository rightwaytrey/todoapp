# TaskMaster

The phone front-end for the tasks that already live in Taskwarrior on the home
server. It replaces Taskchamp, which had two problems that were never going to get
better: the sync is pull-only, so a task added at the desk reaches the phone
whenever the phone feels like it, and the filters are a premium-gated custom
grammar whose date tags are broken on this build — the morning list only works
because a timer on the desktop paints real `+today`/`+overdue` tags onto tasks
so the phone can exact-match them. So: **none of the sync lag, less filter
confusion. Just record tasks on the phone and complete them.**

There is no sync here at all. The phone calls a small HTTP API on the home
server that shells out to `task`, over the tailnet, and the server is the single source of
truth. Taskwarrior stays the store, which is the point — `pa roundup`, the
Pushover reminders, the `+claude` dispatch queue and the Scriptable home-screen
widget all keep working untouched, because nothing underneath them changed. The
client caches locally so it paints instantly and can capture a task with the
phone off the tailnet, then replays the queued writes when it is back. The
decisions and the reasons behind them are in
[`docs/design.md`](docs/design.md); the contract both halves are built to is
[`docs/api.md`](docs/api.md).

## Layout

| Path | What |
|---|---|
| `www/index.html` | **The entire client.** Tasks, Done, Settings, the detail sheet, the offline queue. Vanilla HTML/CSS/JS, no framework, no build step, no external requests. |
| `capacitor.config.ts` | Capacitor 8 shell. App id `org.rightwaytrey.taskmaster`, bundled mode, and two plugins: `@capgo/capacitor-updater` (over-the-air web bundles, self-hosted — `design.md` D11) and `@capacitor/app`. **Every setting in it is native**: changing one needs a store build. |
| `ios/App/App/Info.plist` | Display name, and the scoped ATS exception (`__ATS_DOMAIN__`, stamped at build time) that lets the app talk plain HTTP over the tailnet. Read the comment before touching it. |
| `ios/App/TaskMasterWidget/` | **The home-screen widget.** WidgetKit + SwiftUI, one Swift file, and its own `Info.plist` with its own copy of the ATS exception (ATS is per bundle). It calls the API itself; it does not read anything the app wrote. `design.md` D7. |
| `ios/ExportOptions.plist` | App-store export, automatic signing; CI seds the team id in. |
| `.github/workflows/testflight.yml` | Stamp the build number → `cap sync` → archive unsigned → export signed → upload. **Dispatch only.** |
| `server/` | FastAPI over the `task` CLI, systemd user unit on `:8101`. Its own README. |
| `scripts/mock-api.py` | stdlib-only in-memory stand-in for the API, so the UI can be built in a browser with no Taskwarrior and no network. |
| `scripts/add_widget_target.rb` | Adds the `TaskMasterWidget` extension target to the Xcode project, using the `xcodeproj` gem. Idempotent. The generated target **is committed**; this is how it gets rebuilt from Linux when it is not. |
| `scripts/publish_bundle.py` | Turns `www/` into a live-update bundle in `server/bundles/`. Stamps `__BUNDLE__` in a **copy**, never in the committed file; refuses a client with no `notifyAppReady()`. |
| `scripts/ship_web.sh` | The one command for a web-only change: publish, then verify through the same URL the phone uses. |
| `docs/` | `design.md` (decisions), `api.md` (the contract), `build-plan.md`, `screenshots/`. |
| `SHIP.md` | The one-time Apple setup, then what every build looks like. |

Only `www/index.html` is the client. There is no `src/`, no bundler and no
`dist/`: the file that is committed is the file that runs on the phone. The
copy under `ios/App/App/public/` is generated by `cap sync` and is gitignored —
**editing the HTML without re-syncing changes nothing on the device**, and CI
runs the sync itself, so that trap only exists for a local Xcode build.

## Running the UI in a browser

The client is a static file and works in a desktop browser with no Capacitor at
all, which is where every screen gets built and screenshotted.

Against the mock, which needs neither Taskwarrior nor a network:

```bash
python3 scripts/mock-api.py --port 8111     # one terminal
npm run serve                               # the other: http.server on 8112 over www/
```

Then open <http://localhost:8112/?server=http://localhost:8111>. The `?server=`
parameter is read once on load and stored, so it is also how you point the page
at anything else. `--latency-ms 1500` on the mock is worth knowing about: with a
0 ms loopback server you cannot see whether the optimistic write path
(design.md D6) actually moves the screen before the server answers.

Against the real API, which is the same thing with a different port:

```bash
npm run serve
# http://localhost:8112/?server=http://localhost:8101
```

`:8101` is the live service — it runs as the systemd **user** unit
`taskmaster-api` (`systemctl --user status taskmaster-api`), against the real
`~/.task`, so anything you add or complete there is a real task, with the real
hooks firing behind it. See [`server/README.md`](server/README.md) for running,
testing and deploying it, plus the optional bearer token and the
`tailscale serve` HTTPS upgrade.

## Configuration — the two values that are not in this repo

This repo is public, and the app's own server is not. Two values are therefore
kept out of the tree and stamped in at build time (`design.md` D4):

| Placeholder | In | Holds |
|---|---|---|
| `__API_BASE__` | `www/index.html` (`API_DEFAULT`), `capacitor.config.ts` (`updateUrl`), `ios/App/TaskMasterWidget/Info.plist` (`TaskMasterAPIBase`) | the API base URL the phone uses — scheme, host and port, no trailing slash |
| `__ATS_DOMAIN__` | `ios/App/App/Info.plist`, `ios/App/TaskMasterWidget/Info.plist` (`NSExceptionDomains`) | the ATS exception domain: the bare domain the cleartext exception is scoped to |

Who stamps them:

- **A store build** — `.github/workflows/testflight.yml`, step *Stamp server
  configuration*, from the `TASKMASTER_API_BASE` and `TASKMASTER_ATS_DOMAIN`
  repository secrets (`SHIP.md`). It fails the build if either secret is empty
  or any placeholder survives.
- **An over-the-air bundle** — `scripts/publish_bundle.py`, into its *copy* of
  `www/index.html`, from `TASKMASTER_PUBLIC_BASE`. It refuses to publish
  without it.
- **The server** — `TASKMASTER_BUNDLE_BASE` (or `TASKMASTER_PUBLIC_BASE`) for
  the absolute download URL it hands the phone. No default in code; unset
  means every check is answered "no bundle published".

The last two read the same file, which is **not in the repo**:

```bash
mkdir -p ~/.config/taskmaster
printf 'TASKMASTER_PUBLIC_BASE=http://HOST:8101\n' >> ~/.config/taskmaster/env
chmod 600 ~/.config/taskmaster/env
systemctl --user restart taskmaster-api
```

It is the systemd unit's `EnvironmentFile` as well
(`server/deploy/taskmaster-api.service`), so one line configures the server, the
publish script and `scripts/ship_web.sh`. It must be the **same value** as the
`TASKMASTER_API_BASE` secret: a bundle that disagrees with the shell hands a
phone a default server it cannot reach.

**Unstamped is a working state, not a broken one.** A plain checkout has no
default server: Settings says "Not configured — enter the server URL above", the
widget says "Server not configured", and nothing is fetched until a URL is
entered. `?server=` and a saved value are unaffected, which is exactly how the
UI is developed in a browser (above).

## Building for the phone

```bash
npm ci
npx cap sync ios      # works on Linux; copies www/ into the Xcode project
npx cap open ios      # needs macOS + Xcode; nobody does this
```

The widget extension target is already in the committed `project.pbxproj`, and
`cap sync` leaves the pbxproj alone entirely — verified 2026-09-04, twice over.
If it is ever lost (a Capacitor upgrade, a bad merge), put it back from Linux
with no Xcode:

```bash
ruby scripts/add_widget_target.rb    # needs the xcodeproj gem; no-op if present
```

## Shipping

**There are two lanes, and picking the wrong one is what burns the month's
minutes.** A store build is ~30 billed macOS minutes; a bundle is free
(`design.md` D11).

| What changed | Lane | Cost | Lands |
|---|---|---|---|
| `www/index.html` — anything at all: markup, CSS, JS, a copy fix | `scripts/ship_web.sh "what changed"` (or `python3 scripts/publish_bundle.py --www www --notes "…"`) | **zero Actions minutes** | phones pick it up at their next cold launch |
| `server/**` | `systemctl --user restart taskmaster-api` | none | at once |
| `docs/`, `README.md`, `SHIP.md` | nothing to ship | none | — |
| A Capacitor plugin, `capacitor.config.ts`, `ios/App/App/Info.plist`, icons, the app id | store build | ~30 min | TestFlight, ~10 min of Apple processing, then install |
| `ios/App/TaskMasterWidget/**`, `scripts/add_widget_target.rb` | store build | ~30 min | as above |

Two rules that make the web lane safe:

1. **Nothing over the air works until a store build carrying the updater plugin
   is on the phone.** Until then every published bundle is inert — the installed
   shell is not asking. That build is the one prerequisite of the whole scheme.
2. **A bundle must not depend on a native change an installed shell lacks** — a
   new plugin, a new Info.plist key, a widget that is not there. Gate it:
   `MIN_NATIVE=1.0.9 scripts/ship_web.sh "…"`. The API then answers older
   shells `"needs native 1.0.9"` and withholds it, instead of handing them a
   client that calls a bridge that isn't there. The number is the **Build** line
   on the Settings screen (`1.0.<run number>`), and it sticks in the manifest
   until it is changed.

A bad bundle costs one relaunch, not a broken app: the client calls
`notifyAppReady()` once it has painted, and a bundle that does not reach that
call within ten seconds is rolled back to the previous one. To undo one
deliberately, publish the previous content again as a new version — the store
keeps the current zip plus the five before it (`--keep`).

Then the store lane. [`SHIP.md`](SHIP.md) — the one-time Apple portal and App
Store Connect work, the six repo secrets, then every build. Once that is done a
build is one command:

```bash
echo '{"ref":"main"}' | gh api --method POST \
  repos/rightwaytrey/todoapp/actions/workflows/testflight.yml/dispatches --input -
```

(The repo name `todoapp` there is an assumption — the GitHub repo does not
exist yet. If you create it under another name, fix this line, the same command
in SHIP.md, and the comment at the top of the workflow.)

Dispatch it only with the user's explicit go: it spends real money. There is no
`push:` trigger on purpose. macOS runners bill at 10x, August ran out of minutes
on redundant builds, and since D11 a change to `www/index.html` — which is most
changes — does not need one at all. Re-dispatch every ~90 days regardless:
TestFlight builds expire and the installed app stops launching.
